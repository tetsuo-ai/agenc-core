# Selector v2 evaluation

The production path keeps the connected parent model unless a handoff is adequate, priced and supported. A trusted host can supply independent checks through `SessionServices.childRoutingVerifier`. Ordinary CLI sessions have no such service and use parent-first single-shot routing. A completed child alone never trains correctness.

`calibrate.mts` reads **calibration-only** input and rejects another split. It fits local per-skill abilities and paired failure recovery rates. Its development rows use leave-one-task-out fitting, including latency, availability and conditional recovery. It selects a threshold from the calibration grid at the restricted OpenRouter calibration quality, then minimizes recorded cost. The input includes no reference answers. `evaluate.mts` checks the policy freeze, reuses first matched real provider responses, runs the unmodified frozen grader, and never updates on held-out rows. It replays two settings: the frozen cheap parent (`deepseek/deepseek-flash`) under a $0.05 cap, and the predeclared premium arm (`kimi/kimi-k3`) as an uncapped parent.

Example from the repository root, with a router-bench directory restored from the evaluation archive (see below):

```sh
node_modules/.bin/tsx runtime/eval/selector-v2/calibrate.mts calibration-input.json calibration.json
node_modules/.bin/tsx runtime/eval/selector-v2/evaluate.mts /path/to/router-bench calibration.json policy-freeze.json evaluation.json
python3 runtime/eval/selector-v2/evidence/summarize.py evaluation.json out
```

The scripts, report, frozen hashes and small summaries are in `evidence/` next to this file. The raw replay files are in the evaluation archive. External benchmark responses are not generated by selector priors. Subscriptions with unknown dollar cost are excluded from dollar comparisons. The live Linux daemon runs use isolated homes and count both parent and child calls; they are separate from direct replay.

## Decision math

For each eligible model, utility is `p - lambda * dollars - mu * seconds`. Under a dollar cap, `lambda = willingness / max(0.001, remainingTaskBudget)` with willingness 0 for quality, 0.025 for balanced and 0.25 for economy. Without a cap, `lambda` is 0: price never moves a child off its parent's model, and an uncapped session is never more price averse than a capped one. Under balanced, price weighs too little against the handoff margin and uncertainty to move an adequate parent; economy lets an adequate cheaper model win when it saves much of the cap. `mu` is 0.0002 normally and 0.01 for fast. These are explicit policy conversion factors, not measured universal preferences. Dollar caps still come from the atomic admission kernel. The user can request `routing_preference`, `routing=inherit`, or explicit provider/model.

Model-specific context, output, tools, vision, reasoning, connected authority, allowlists, health and pricing filters run first. A model then needs evidence that it is adequate for the task: its maintained tier quality for the task kind must meet the floor for the task's complexity (0.65 simple, 0.80 standard, 0.92 hard), as in the first selector. The floor binds the parent too. A parent below it hands a task to an adequate model, and when none is adequate the child keeps the parent's model without a routing plan. A parent with no maintained profile has unknown quality and stays the default.

A different model must improve utility by more than its extra 512 context tokens, 750 ms handoff estimate, 0.01 utility margin, and an uncertainty penalty of 0.1 times the sum of the candidates' predictive interval widths. Maintained tiers establish adequacy, not superiority: a higher predicted quality counts toward that gain only when at least three verified outcomes put the destination's lower 95% bound above the current choice's expected quality. A lower one always counts. A hard task never moves to a model rated below the current choice. Unknown-price subscriptions cannot create an apparent cost saving. When the parent cannot take the task, the least expensive adequate model does, with or without a cap, so a cap never makes the child more expensive; only verified outcomes can justify a more expensive model.

Abilities use `p = sigmoid(a * (theta - difficulty))` for coding, reasoning, tool use, long context and extraction. Content length, conditional structure, code/math terms and actual tool-work terms determine difficulty locally. No task IDs, reference answers or author difficulty labels enter IRT. No installed local embedding model was available; there is no remote embedding call or download.

Each ability has a Gaussian prior and an online Laplace approximation after independent Bernoulli verdicts: `v' = 1 / (1/v + a*a*p*(1-p))`, `theta' = theta + v'*a*(y-p)`. Prediction includes the logistic-normal approximation and a transformed 95% interval. Variance has a numerical floor. The posterior is approximate and small-sample probabilities are uncertain. Infrastructure failures affect a separate availability estimate and cooldowns, never ability labels. Versioned abilities and receipt IDs are persisted locally with bounded, atomic writes. An ability from another IRT revision is dropped on its own when the file is read; it never takes health blocks or receipts with it. A delayed verifier verdict does not count execution or dollars twice.

Every prior comes from the maintained tier on one scale: at the reference difficulty of -1 it equals the tier quality of the skill's kind (coding, reasoning, extraction; general for tool use; research for long context), with variance 1.5. An unprofiled model starts neutral. The frozen evaluation also used vendor benchmark priors for a few DeepSeek and Meta models. They compared different benchmarks between models (GPQA Diamond for flash against HLE for v4-pro, and mixed coding and tool benchmarks), so the review removed them and changed the IRT revision.

A verified cascade searches eligible first models with the parent as escalation anchor. It minimizes `c1 + (1-p1)*c2` at a predicted quality threshold, including both verifier costs and latencies. Predicted quality is `p1 + (1-p1)*P(parent passes | first fails)`. The conditional term comes from paired calibration/local evidence. A pair's row counts only when its raw counts show the parent rescuing the first model at least once in at least two of its failures; Beta(0.5, 0.5) smoothing then shapes the estimate. A row without a rescue, a lone failure or a missing row supplies zero gain, not an independence assumption. A cascade is planned only when such a row, or verified outcomes that put the first model above the current choice, back it. The full possible chain cost must fit the cap. Every retry gets fresh authority, consent, identity and remaining budget. Unknown usage under a cap or verifier errors stop; safe replay after tools needs a host attestation. The host is responsible for routing any paid verifier through admission and providing its bounded charge.

Thompson sampling is explicitly opt-in and cannot select outside the eligible set. It requires local observations and a conservative upper bound on quality, price and latency loss of at most the configured envelope (maximum 0.05). The cold/uncertain path falls back to the parent. No benchmark benefit is claimed for exploration: the evaluation disables it.

## Trusted verifier integration

The optional host service's `prepare({prompt, features})` returns a `TrustedChildVerification` with `check(terminal)`, retry safety, cost/latency and optional paired recovery evidence. It is not accepted in `spawn_agent` arguments. A `prepare` that throws, takes more than 10 seconds or returns no usable check ends the spawn with a confirmed no-spawn error. Checks must examine exact answers/artifacts using tests or an independent verdict. They must not accept the child saying it passed. No arbitrary shell verifier is exposed by this change.

Without paired evidence the host can still check each attempt and build local ability history. Provider failures before a tool call still fall back through the ranked candidates, and each answer is checked. Only a planned cascade starts another attempt after a failed check. A check runs whenever an attempt left an answer, also when its usage is unknown or held and no cap needs the number. The parent's final routing message names a verdict only for a check that ran, and otherwise says why none ran. Results and failures retain separate durable attempt receipts. Consumers must wait for the final routing message before accepting a verified answer. This change does not replace individual child receipts with one durable aggregate cascade receipt; persistence/restart of a partially completed cascade is not implemented.

## Replay

Restore a router-bench directory: copy `evidence/benchmark/bench_tasks.py`, `TASKS.md`, `candidates.json` and `freeze.json`, then `tasks.json` and `direct-v1/records.jsonl` from the archive. `python3 bench_tasks.py verify` there checks the frozen hashes. Use the repository's Node 26 toolchain. No inference endpoint is called by replay.

**Frozen policy.** `portable-policy-freeze.json` pins the source evaluated before the review. The archive's `frozen-source.tar.gz` holds that source with its evaluation folder, whose `evidence/` still has the raw files and a README with the replay steps; its selector files match the freeze. To replay, extract it into an empty folder, link the repository's `node_modules` beside its `runtime`, decompress the two calibration files in `runtime/eval/selector-v2/evidence`, and run from there `tsx ../evaluate.mts benchmark calibration.json portable-policy-freeze.json replay.json`. The freeze records one post-evaluation change: inserting "and" in the unavailable-model rejection text to preserve an existing test contract. All 378 decisions, verdicts, request IDs and costs replay identically. The exported matrix drops unused private accounting fields, so its file hash differs from the original; request IDs, prompts, answers, grades, token usage and dollar fields remain unchanged.

**Post-review policy.** `post-review-policy-freeze.json` pins the selector after both review rounds and a refit by `calibrate.mts` on calibration data only. Decompress `calibration-input.json.gz` and copy `post-review/calibration-post-review.json` from the archive into `evidence/`, then run, from there:

```sh
../../../../node_modules/.bin/tsx ../evaluate.mts /path/to/router-bench calibration-post-review.json post-review-policy-freeze.json evaluation-post-review.json
python3 summarize.py evaluation-post-review.json post-review
```

The held-out tasks and the frozen policy's held-out results were public before this refit, so it is not a blind held-out result. `post-review-tables.md` and `post-review-metrics.json` hold its summary; `REPORT.md` discusses it.
