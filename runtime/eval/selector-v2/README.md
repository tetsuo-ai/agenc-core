# Selector v2 evaluation

The production path now retains the connected, allowed parent unless supported utility gain exceeds handoff cost and uncertainty. A trusted host can supply independent checks through `SessionServices.childRoutingVerifier`. Ordinary CLI sessions have no such service and use parent-first single-shot routing. A completed child alone never trains correctness.

`calibrate.mts` reads **calibration-only** input and rejects another split. It fits local per-skill abilities and paired failure recovery rates. Its development rows use leave-one-task-out fitting, including latency, availability and conditional recovery. It selects a threshold from the calibration grid at the restricted OpenRouter calibration quality, then minimizes recorded cost. The input includes no reference answers. `evaluate.mts` checks the policy freeze, reuses first matched real provider responses, runs the unmodified frozen grader, and never updates on held-out rows.

Example from the repository root, with an externally frozen router-bench directory:

```sh
node_modules/.bin/tsx runtime/eval/selector-v2/calibrate.mts calibration-input.json calibration.json
node_modules/.bin/tsx runtime/eval/selector-v2/evaluate.mts /path/to/router-bench calibration.json policy-freeze.json evaluation.json
```

The exact replay artifacts, plot script, frozen hashes and report are in `evidence/` next to this file. External benchmark responses are not generated by selector priors. Subscriptions with unknown dollar cost are excluded from dollar comparisons. The live Linux daemon runs use isolated homes and count both parent and child calls; they are separate from direct replay.

## Decision math

For each eligible model, utility is `p - lambda * dollars - mu * seconds`. `lambda = willingness / max(0.001, remainingTaskBudget or 0.05)` with willingness 0 for quality, 0.025 for balanced and 0.25 for economy. `mu` is 0.0002 normally and 0.01 for fast. These are explicit policy conversion factors, not measured universal preferences. Dollar caps still come from the atomic admission kernel. The user can request `routing_preference`, `routing=inherit`, or explicit provider/model.

A different model must improve utility by more than its extra 512 context tokens, 750 ms handoff estimate, 0.01 utility margin, and an uncertainty penalty of 0.1 times the sum of the candidates' predictive interval widths. Model-specific context, output, tools, vision, reasoning, connected authority, allowlists, health and pricing filters run first. Unknown-price subscriptions cannot create an apparent cost saving.

Abilities use `p = sigmoid(a * (theta - difficulty))` for coding, reasoning, tool use, long context and extraction. Content length, conditional structure, code/math terms and actual tool-work terms determine difficulty locally. No task IDs, reference answers or author difficulty labels enter IRT. No installed local embedding model was available; there is no remote embedding call or download.

Each ability has a Gaussian prior and an online Laplace approximation after independent Bernoulli verdicts: `v' = 1 / (1/v + a*a*p*(1-p))`, `theta' = theta + v'*a*(y-p)`. Prediction includes the logistic-normal approximation and a transformed 95% interval. Variance has a numerical floor. The posterior is approximate and small-sample probabilities are uncertain. Infrastructure failures affect a separate availability estimate and cooldowns, never ability labels. Versioned abilities and receipt IDs are persisted locally with bounded, atomic writes. A delayed verifier verdict does not count execution or dollars twice.

Public benchmark priors are weak log-odds anchors with variance 1.5. Half-logit shrinkage limits the influence of incompatible benchmark harnesses/efforts. Exact named sources and dates are in `provider-selector-irt.ts`: DeepSeek release notes (2026-09-10, 2026-08-13) and Meta's model page (undated, retrieved 2026-09-29). Scores from older Kimi or OpenAI versions are not silently assigned to current model names. Unsupported skills/models get a neutral prior. These vendor metrics are not probabilities of passing router-bench.

A verified cascade searches eligible first models with the parent as escalation anchor. It minimizes `c1 + (1-p1)*c2` at a predicted quality threshold, including both verifier costs and latencies. Predicted quality is `p1 + (1-p1)*P(parent passes | first fails)`. The conditional term comes from paired calibration/local evidence with Beta(0.5, 0.5) smoothing; absent evidence supplies zero gain, not an independence assumption. The full possible chain cost must fit the cap. Every retry gets fresh authority, consent, identity and remaining budget. Unknown usage or verifier errors stop; safe replay after tools needs a host attestation. The host is responsible for routing any paid verifier through admission and providing its bounded charge.

Thompson sampling is explicitly opt-in and cannot select outside the eligible set. It requires local observations and a conservative upper bound on quality, price and latency loss of at most the configured envelope (maximum 0.05). The cold/uncertain path falls back to the parent. No benchmark benefit is claimed for exploration: the frozen evaluation disables it.

## Trusted verifier integration

The optional host service's `prepare({prompt, features})` returns a `TrustedChildVerification` with `check(terminal)`, retry safety, cost/latency and optional paired recovery evidence. It is not accepted in `spawn_agent` arguments. Checks must examine exact answers/artifacts using tests or an independent verdict. They must not accept the child saying it passed. No arbitrary shell verifier is exposed by this change.

Without paired evidence the host can still check a single attempt and build local ability history. Only a planned cascade can escalate after a failed check. Results and failures retain separate durable attempt receipts; the parent receives routing progress and a final routing notice. Consumers must wait for that final routing notice before accepting a cascaded answer. This change does not replace individual child receipts with one durable aggregate cascade receipt; persistence/restart of a partially completed cascade is not implemented.

## Portable replay

The committed evidence includes the frozen public tasks/graders, stripped real provider records (no headers, balances or reasoning), compressed calibration inputs/results, and portable source hashes. From this folder:

```sh
cd evidence
gzip -dk calibration-input.json.gz calibration.json.gz
../../../../node_modules/.bin/tsx ../evaluate.mts benchmark calibration.json portable-policy-freeze.json replay.json
```

Use the repository's Node 26 toolchain. `policy-freeze.json` preserves the original absolute manifest. `portable-policy-freeze.json` maps its digests to relative paths and explicitly records one post-evaluation change: inserting "and" in the unavailable-model rejection text to preserve an existing test contract. Routing behavior and the fitted policy are unchanged; all 378 decisions, verdicts, request IDs and costs replay identically. A later notification fix makes every independent verdict visible to the parent and does not affect the direct policy. The exported matrix drops unused private accounting fields, so its file hash differs from the original; request IDs, prompts, answers, grades, token usage and dollar fields remain unchanged. No inference endpoint is called by replay. Calibration can be rerun from its compressed input without reading held-out data. `python3 summarize.py` regenerates the tables and PNG with matplotlib.
