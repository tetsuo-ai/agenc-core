# Runtime overhead replay

Set `AGENC_RUNTIME_TIMING=/absolute/task-owned/path/timing` before starting the daemon. Each process buffers payload-free JSONL spans into `<prefix>.<pid>.jsonl`. The switch is read once at module load. Restart an existing daemon with this switch to trace its work. No prompt, arguments, result bodies, credentials, or file paths are recorded. Diagnostic write failures do not change runtime outcomes. Disabled instrumentation avoids timers, writes, and clock reads.

Spans use epoch milliseconds backed by the process monotonic clock. Nested spans are inclusive and must not be summed. `model.request` encloses the physical provider call; `admission.model` ends immediately before that call. `tool.invoke` encloses a tool's admitted dispatch implementation, including permission/sandbox/wrapper work; it is not pure child-process time. `tool.admitted` includes effect intent, dispatch, receipt, and settlement. `receipts.commit` includes both canonical commit and projection. `projection.thread_index` is a rebuildable display/history index, never effect admission. `persistence.fsync` counts explicit rollout syncs only; SQLite native syncs need the optional preload below.

Run `replay.py` in a Linux Node 26 container with its own writable `/work` and read-only benchmark sources at `/evidence/light-ultra` and `/evidence/light-port`. Copy the benchmark `bench/tasks` to `/work/bench/tasks`. Build the target Core under `/work/<core>`. Use the host user's UID to satisfy normal protected-directory ownership checks.

```
python3 replay.py --core core-instrumented --label before --repeats 2
python3 replay.py --core core-candidate --label after --repeats 2
python3 summarize.py /work/replay-runs before > before.json
```

Use `--modes daemon,cold,warm` for all three paths. Build the SDK driver once per target from its runtime directory with `../node_modules/.bin/esbuild benchmarks/runtime-overhead/daemon-client.ts --bundle --platform=node --format=esm --outfile=benchmarks/runtime-overhead/daemon-client.mjs`. The same source driver must be bundled against each target SDK.

Primary `daemon` mode uses an existing SDK connection. It first creates and stops a model-free session to prime the daemon and workspace, then times session create, attach, turn and stop over that connection. Client startup/import/connect and priming are excluded; priming is reported separately. This is the daemon RPC path, not a Desktop UI benchmark. Cold starts a daemon per task. Secondary `warm` starts the daemon before timing the same new-session CLI request, without session priming. Every run has its own project, home, daemon and span files. All modes stop only that task's daemon afterward. The benchmark measures real replayed tools. Primary inter-call overhead uses the scripted server's response-flush and next-request timestamps, subtracting the union of tool intervals (including gaps between tools). Provider API spans also remain available. No model-compute time is introduced. Subtract tool intervals from task wall time for runtime outside tool dispatch. Broad task test commands remain real work. Replay serves recorded OpenAI tool sequences without upstream calls or artificial delay. It rewrites recorded benchmark repository paths to the fresh task repository and maps recorded process handles to live tool results. Commands followed by a recorded poll yield after 1 ms so the poll remains meaningful without the original model think time; their commands and real work are unchanged. Adjusted call IDs and mapping failures are recorded. A missing live handle fails the replay rather than polling an unrelated process. It does not infer model quality or make new decisions from tool results. All recorded call counts and check outcomes are retained. Task 12 uses the explicitly recorded confirm-screen source because the round2-new cohort did not contain it.

Port replay uses `--traces /evidence/light-port/runs --prefix candidate-local-confirmation-deepseek-flash`. Use unique labels; existing or incomplete runs are never overwritten. Only task-owned files may be written by the container. Keep the evidence mounts read-only and do not expose user homes or provider credentials.

For native fsync/fdatasync and regular-file write counts (including SQLite), compile `native-io.c` with `cc -shared -fPIC -O2 native-io.c -o /work/native-io.so`, then add `--modes warm --native-io /work/native-io.so`. This starts a foreground diagnostic daemon because normal daemon autostart deliberately sanitizes loader variables. This Linux diagnostic preload forwards the original syscalls and preserves errno; it records counts and successful byte lengths, never payloads or paths. Pipe/socket writes and diagnostic output files are excluded. Native logs go to `<prefix>.<pid>.native.jsonl`. This adds syscall overhead, so use separate diagnostic runs, not primary wall-time comparisons. Native records use CLOCK_REALTIME; do not compare spans across clock adjustments.

A crash can lose buffered timing records. They are evidence, not a recovery journal. Durable canonical events, SQLite FULL sync, permission admission, sandbox execution, effect intents and receipts remain authoritative.

See `REPORT.md` and `round2-evidence.json` for Round 2 SDK/cold/CLI tables and limits. `ROUND1.md` preserves the original comparison with main. Its replay, paid-check and test evidence remain in `evidence.json`, `flash-evidence.json` and `test-evidence.json`. `baseline-instrumentation.patch.gz` applies to the pinned main revision in that report. Round 2 targets of 1.0 s/task and 40 ms mean inter-call overhead remain unmet; warm session creation averages 97 ms.
