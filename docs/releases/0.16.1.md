# AgenC 0.16.1

AgenC 0.16.1 is a repair release. It makes the one-line installer work on
stock macOS, which 0.16.0 broke for every Mac; gives the installer a live
progress display; removes the same latent macOS trap from the npm launcher;
and fixes a supervision race that misreported successful commits as process
leaks on loaded machines.

## Installer

- **`curl -fsSL https://get.agenc.ag/install.sh | sh` works on stock macOS
  again.** The system-tool resolver required every trusted executable to have
  exactly one hard link, but Apple ships `/usr/bin/unzip` and
  `/usr/bin/zipinfo` as two names for one inode, and `/usr/bin` is immutable
  under SIP — so provenance verification failed on every Mac with no
  user-side workaround. The resolver now relies on what actually carries the
  guarantee: root ownership, no group/other write, and a fully root-owned
  directory chain, none of which a non-root user can forge. The four
  single-link checks covering artifacts the installer downloads into its own
  private tree are untouched, and the packaging suite now pins both halves of
  that contract so neither can drift silently. This fix was promoted to the
  stable installer channel on 2026-08-15 through the installer-hotfix lane;
  0.16.1 is the first versioned release whose sealed assets carry it.
- **The installer shows what it is doing instead of narrating it.** On a
  terminal, the runtime download renders a live progress bar measured by the
  same byte counter that enforces the manifest's exact-size contract — real
  transferred bytes against the declared size, not an estimate — and each
  completed phase collapses to a one-line result. With stderr redirected
  (CI, `2>file`), output stays byte-identical to the previous plain log,
  verified by diffing full installs, and `--verbose` restores that log on a
  terminal. Warnings keep their `agenc-install:` prefix so they stand out
  against the checkmarks rather than being dressed up as one.

## npm launcher

- **The launcher no longer requires its trusted system tar to be
  single-linked.** `@tetsuo-ai/agenc` carried the same rule that broke the
  shell installer on macOS; it survived only because Apple happens not to
  hardlink `tar` today, and a platform shipping `tar`/`gtar` as one inode
  would have failed with no user-side fix. Same reasoning as the installer
  change, same preserved boundary: files the launcher downloads into its own
  tree still fail closed on a second link, and a count-pinned test keeps the
  private-tree checks from being dropped silently.

## Runtime

- **A helper still tearing itself down no longer counts as a leaked
  process.** Supervised process teardown classified anything visible in the
  instant its leader closed as `residual_process`, but on a loaded machine a
  git helper routinely outlives its leader by a few scheduler quanta — so
  commits that exited 0 were reported as failed. Members of a Linux cgroup
  boundary now get a bounded settle window (two consecutive quiet polls)
  before classification. The window applies only where containment makes the
  observation authoritative: the Linux subreaper, the darwin process gate —
  which settles its own process group during teardown, leaving residue
  observable only at close — and Windows job objects still classify
  synchronously, byte-for-byte as before. Under a load that reproduced the
  failure five times in six runs, the fix produced zero in eight; a genuine
  leak, which containment keeps visible for the whole window, is still
  reported exactly as it always was.
