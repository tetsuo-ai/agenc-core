# AgenC 0.19.0

AgenC 0.19.0 adds task budget controls and TUI updates. It also fixes budget
accounting that could stop a task early when provider usage exceeded an estimate.
These changes are relative to 0.17.0, the last published release. Version 0.18
was never published.

## Light execution and storage

- Eligible non-interactive print runs using
  `--dangerously-bypass-approvals-and-sandbox` select fast mode automatically.
  This explicitly bypasses both approvals and the OS sandbox. It batches
  persistence work at request and completion boundaries. `--bypass-approvals`
  keeps the sandbox and does not select this fast mode. Set `bypassFastMode`
  to `false` to keep synchronous persistence boundaries. Interactive, resumed
  and `--full-durability` runs keep the normal loop.
- On Linux, eligible shell commands reuse a session sandbox. Reuse depends on
  the permission policy, environment, working directory and filesystem
  identities still matching. Unsupported commands use a separate sandbox;
  a startup failure keeps the separate-command path for the rest of the
  session. Each command still receives admission and cleanup checks.
- SQLite WAL autocheckpoint runs less often, keeping automatic checkpoint work
  out of more command commits. Normal commits retain FULL synchronization and
  relaxed one-shot execution still seals its durable state at completion.
- Startup uses prepared runtime entrypoints and native helpers, and fresh
  state databases start from the current schema.

## Task budgets

- Choose `eco`, `balanced`, or `max` with `--budget`, for example
  `agenc --budget eco -p "Fix the failing test"`. Eco uses a smaller task
  token allocation, balanced uses the standard allocation, and max removes
  the task token cap. These are budget policies, not reasoning-effort settings.
- `/budget` opens a picker with eco, balanced, max and Custom token caps.
  `/budget eco`, `/budget balanced`, `/budget max`, or a number such as `3m`
  applies to the current session and saves the choice for new sessions.
  Use `0` for no task token cap. Explicit CLI or project settings can override
  the saved choice.
- Interactive tasks reach a budget checkpoint instead of a hard stop. Choose
  Continue to extend the allowance, Remove the limit for this task, or Stop here.
  Escape selects Stop here. Usage stays recorded. Headless and background work
  retain hard caps. Independent spending limits still apply.
- Retries, auxiliary model calls and delegated agents share the session/run
  allocation. Use a fresh session for each independent task. Unknown usage
  retains its reservation across restart.
- Independent call limits, provider context limits and monetary limits still
  apply with max. A task token allocation controls admission of work;
  provider-reported usage can exceed an estimate for an already admitted call.
- Provider usage above a reserved input estimate no longer causes an early
  `provider_overrun` stop while the shared task allocation can cover it.
  DeepSeek input estimates are more conservative. Explicit provider and tool
  contracts and hard monetary limits remain enforced.
- Cached input is included in task usage. Providers that report uncached input
  separately from cached input now count both in local and durable accounting.

## Defaults

New sessions use balanced unless a saved choice, project setting or CLI
option overrides it. Model verbosity remains unset, keeping the provider
output policy. Verbosity and the task token budget are separate settings.

Without a saved theme, the TUI uses olive, cream and wine. Set `tui.theme` to
`"dark"` for the previous black and purple look. Set it to `"auto"` for olive on
dark terminals and light on light terminals. Saved explicit themes are kept.

## Evaluation

The round's report does not establish an overall advantage over Pi in tasks
solved, whole-task time, or token use. It reports no demonstrated difference
for the final locked answer-to-next-request comparison. The sealed comparison
predates the budget fix and cannot validate the new default. The automatic
patience stop detector is dropped from this round.

## Upgrade notes

Existing sessions retain their saved budget until you change it with `/budget`.
The embedding SDK remains independently versioned and is not published by this
Core release.

- The footer fits on one row with context and cost. While helpers work in swarm
  mode, it shows `swarm (N)`. The theme accent grows stronger with the count and
  becomes bold at six helpers. It returns to `swarm` when helpers finish, are
  cancelled or fail. Finished helpers no longer count again after cancellation.
- Long prompts wrap without cutting the second row or misplacing the cursor.
- Shift+Tab cycles permission modes. Option+M also works on an empty macOS
  prompt, including terminals that send µ. Inside a draft, µ remains text.
  Alt+M is the fallback on other platforms. Digits no longer pick a mode in
  the popup. Use `/permissions` to pick directly. On an empty prompt, `?` opens
  or closes shortcut help without inserting a question mark.
- Helper agents on GPT models now start and report back in swarm mode. Their
  spawn and wait calls were previously refused.
- In Light sessions, swarm mode now tells the model how to load the helper
  tools. It previously said they were unavailable, so the model kept all the
  work to itself.
- Restored tool results retain integrity seals after a daemon restart. The next
  tool call no longer fails because a recovered result lacks its seal. A
  conversation cleared with `/clear` also stays cleared after restart.
- At startup, AgenC checks for a newer release in the background. Choose Update
  now, Skip this version or Not now. `/update` shows installed and latest
  versions and installs verified standalone updates. npm installs show the npm
  command. `DISABLE_AUTOUPDATER=1` or `autoUpdates = false` disables the startup
  check. Typing still works after `/resume` and `-c` with the updater enabled.
- Permission deny rules were not enforced from the daemon TUI in unreleased
  0.18 builds. They are now enforced before approval.
- `/hooks` opens a read-only event list in the daemon TUI. `/hooks test` and
  `/hooks clear-diagnostics` are unavailable there.

## Resuming compacted sessions across versions

Manual `/compact` now accepts a short conversation when the summary saves at
least 20% of the source tokens. Automatic compaction keeps its existing minimum
of 1024 tokens and 20%. A manual commit saving fewer than 1024 tokens records an
explicit `manual_proportional` accounting policy and requires AgenC 0.19.0 or
later to resume. The successful compaction displays that requirement. Other
compaction commits retain their existing reader requirement.

Core 0.18.x safely refuses these short commits before model execution. Its
existing diagnostic says `canonical compaction_committed payload does not match
the runtime schema`; for a session containing a marked short commit with
`minimum_reader_runtime: "0.19.0"`, this indicates an unsupported reader rather
than corrupted history. Do not remove the policy marker, lower the reader floor,
or edit the journal to work around the refusal.

Keep the same AgenC home and workspace, upgrade the installation, and restart
its daemon before selecting the session in `/resume`. Once 0.19.0 is published,
standalone installations can use `agenc update --pin 0.19.0`; npm installations
can use `npm install -g @tetsuo-ai/agenc@0.19.0`. Then run
`agenc daemon restart` and check `agenc --version`. During release-candidate
validation, stop the older daemon and launch the same home/workspace with the
built 0.19.0 candidate. No journal conversion is required: the newer runtime
validates the marked commit and resumes its saved conversation directly.

The 0.19.0 reader diagnoses a future unsupported compaction reader floor as an
upgrade requirement before general payload validation, so it does not present
that case as corruption.
