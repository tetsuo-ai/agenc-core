# AgenC 0.14.2

AgenC 0.14.2 restores reliable tool use when old workspace mutation state
outlives the temporary workspace that created it. It also records definitive
shell outcomes so an ordinary failed command does not poison later workspace
mutations. No manual quarantine cleanup is required.

## Deleted workspace quarantine

- A valid quarantine record whose workspace directory was later deleted no
  longer blocks tools in every other project. The record remains on disk and
  is scoped to operations that could overlap its persisted workspace path.
- AgenC still fails closed for an overlapping workspace while that path cannot
  be resolved safely. If the original directory reappears with the same path
  identity, its protected editor authority is recovered from the existing
  quarantine record.
- Invalid, tampered, colliding, or retargeted quarantine identities remain
  hard failures. This patch narrows the blast radius without weakening the
  workspace authority boundary.

## Authoritative shell outcomes

- A shell process that exits, including with a nonzero status, now carries an
  authoritative committed-effect receipt. AgenC no longer mistakes a known
  command failure for an unknown effect that must block future mutations.
- Rejections that occur before a process is spawned, such as invalid input,
  an out-of-bounds workdir, or workspace write policy denial, carry explicit
  no-effect evidence.
- Yielded long-running processes retain their process identity and committed
  effect evidence for later interaction.

## Upgrading

Standalone installs: `curl -fsSL https://get.agenc.ag/install.sh | sh`

npm installs: `npm install -g @tetsuo-ai/agenc@0.14.2`

Existing workspace mutation records are preserved. The daemon applies the
new scoping and effect-disposition behavior when it next loads them.
