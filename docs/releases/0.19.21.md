# AgenC 0.19.21

AgenC 0.19.21 fixes three problems. On macOS a stuck drive could stop AgenC
from starting, some PreToolUse hook denies were ignored, and on macOS process
listings could show values from the process environment. Light now calls the
Skill tool when skills are installed. The release also keeps the Ollama Cloud
freshness mark honest, makes workspace-relative paths work for LSP and notebook
tools on Windows, and adds sandbox and permission tests.

## Hooks

- A PreToolUse hook that denies a tool call now blocks it, even when its output
  has fields AgenC does not know. Before, that output was treated as invalid
  and the call went ahead. A deny wins over a conflicting allow, and a deny
  without a reason shows "Blocked by PreToolUse hook" (#3326).
- Hook matchers accept the tool names other agent tools use. `Bash` matches
  exec_command, system.bash and PowerShell. `Read` matches FileRead and
  NotebookRead (#3326).

## Process arguments

- On macOS, `ps` and `pgrep -lf` could show values from an AgenC process's
  environment, such as API keys, as if they were command-line arguments. AgenC
  now sets process titles only on Linux and Windows (#3329). If you shared a
  process listing from a Mac running AgenC, for example in a bug report, rotate
  the provider keys it could contain.
- Teammates started in tmux or iTerm panes read their environment from a
  private launch file that is removed after use. Before, the pane command
  carried the values, so they could appear in process arguments and shell
  history (#3329).

## macOS startup

- The SQLite lock check ran `/sbin/mount` at every start. That command waits on
  every mounted filesystem, so one stuck drive made AgenC hang at start. The
  check now asks `df` about the lock folder only and stops after 2 seconds.
  The rules for which filesystems count as local are unchanged, and the install
  scripts carry the same fix (#3325).

## Light

- When skills are installed, Light loads the Skill tool before the first model
  call, so the model calls Skill instead of reading SKILL.md through the shell.
  Sessions without installed skills send the same first request as before
  (#3331).

## Ollama Cloud model rows

- An Ollama Cloud model row is now marked with the time Ollama answered for
  it. Reading the row again from the resolver's own cache no longer makes it
  look new, so the 15-minute reuse window cannot grow without a request to
  Ollama. A second session in the same daemon that reuses the first session's
  download gets that download's time and still skips the extra read before
  its first request (#3243).

## Windows

- Workspace-relative paths for LSP diagnostics, NotebookRead and NotebookEdit
  now work on Windows. Before, every relative path was refused as outside the
  workspace because the check expected forward slashes (#3300).
- The CSV output boundary on Windows now accepts a parent folder whose
  inherited permissions only let other accounts add new entries, as
  `C:\Windows\Temp` grants. Grants that can replace, delete or change entries
  are still refused (#3300).

## Tests

- New tests cover sandbox permission parsing, exec policy decisions, network
  host and prefix rules, Windows executable names, path grants, and the
  confinement of worktree and read-only sub-agents (#3315).

## Upgrade notes

Standalone installations update with `agenc update`; npm installations with
`npm install -g @tetsuo-ai/agenc@0.19.21`; Homebrew installations with
`brew upgrade tetsuo-ai/agenc/agenc`. Then run `agenc daemon restart`.
