# AgenC 0.19.28

AgenC 0.19.28 adds tracked background commands, closes withdrawn input forms in the daemon TUI, and fixes child tool
calls, token-count isolation and update result delivery. New-file writes on Linux avoid a helper startup when the
parent folder already exists.

## Background commands

- `exec_command` accepts `background: true` for long jobs. It returns a session ID after about a second; AgenC can
  poll the output, stop the job, and clean it up when the session ends (#3355).
- Commands that reach `timeoutMs` continue as tracked sessions by default. Set `exec_hard_timeout = true` in
  `config.toml`, or `AGENC_EXEC_HARD_TIMEOUT=1`, to restore the hard timeout. Interrupts, run deadlines, explicit
  stops and session cleanup still stop commands. A conversation's eight-session limit also bounds explicit
  background starts and timeout continuations (#3355).
- AgenC reports background jobs that finish between tool calls and gives process-state information when a job has
  printed nothing for a minute. On Linux it also tells the model when container CPU or memory limits are tighter
  than the host totals (#3355).
- Linux sandbox commands keep private network namespaces. For a local server check, AgenC is directed to start the
  server, wait for readiness, run its clients and stop it in one command. A background server is not reachable over
  loopback from a later command, even in the same conversation (#3355).
- In a 68-run DeepSeek Flash A/B, both versions solved all 34 runs per arm. The new version used 7% fewer tokens.
  Wall time increased by 65 seconds, within the measured 84-second replicate gap; this is not a speedup claim
  (#3355).

## Input forms

- When a tool withdraws an input form, the daemon TUI closes that exact form automatically. You can continue typing
  without pressing Escape. Normal answers, validation errors and user cancellation still work.
- A delayed answer to an old form cannot answer a replacement that reuses its address. Reconnecting clients get the
  current pending forms instead of reopening forms that have already settled.
- Daemon protocol 1.36 negotiates these features. Older clients keep the existing response path and receive no close
  events. Close events are live notifications and are not written into canonical journals.

## Reliability

- Child agents can call eligible nested tools through code mode using their own turn and permission context. Parent,
  sibling and stale turn contexts remain rejected.
- Native token-count caches and requests in flight are isolated by counter authority, so one session cannot reuse
  another authority's result or failure. Requests using the same counter still share cached results.
- A TUI following an update retains its unread restart result, including published successor results, even if newer
  restarts push it beyond the usual eight-entry history. When the TUI resumes, the final result replaces the waiting
  notice immediately. Both the following client and result writer must support retention; older clients and writers
  retain their existing behavior.

## Linux file writes

- Creating a file in an existing folder uses a verified, held directory descriptor instead of launching a Node
  helper. Exclusive creation refuses competing files and symlinks, and a renamed parent cannot redirect the write.
  Missing parent folders and platforms without this capability keep the existing helper path.
- In fixed-call daemon TUI checks, affected create gaps fell by about 16 to 18 ms. Both registered 44-cell paid
  panels passed, with all 22 runs solved on each arm in each lane. Outside-provider time fell 10.2% on Luna and
  6.0% on DeepSeek; DeepSeek wall and token differences remained within replicate variation.
