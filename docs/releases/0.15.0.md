# AgenC 0.15.0

AgenC 0.15.0 fixes the ways a local daemon could fight with itself, and makes
the TUI stop advertising keys it did not implement or hiding the part of an
error you need. Every change here came out of driving a source build of 0.14.2
as an ordinary user.

## Daemon startup and port ownership

- A daemon whose home is isolated through a `HOME` override no longer dies when
  the fixed websocket port is already held. It binds an ephemeral port instead
  and logs which port it took. An explicitly configured port still fails on
  collision, because a port you asked for is not one AgenC may silently change.
- The daemon records the websocket URL it actually bound in
  `daemon-runtime.json`. `agenc remote` reads that URL instead of assuming the
  default port, so a client no longer reaches whichever daemon happened to win
  the port. `AGENC_DAEMON_URL` still overrides both. The field is optional on
  read, so a daemon started by an older build is not mistaken for a corrupt
  record.
- Daemons left behind by earlier installs are now stopped. A home has exactly
  one pid file, so a second live daemon for it was untracked by construction:
  nothing ever stopped it, and it competed for the same state and port.
  Discovery previously matched only the current runtime's entrypoint, which a
  superseded install never has. The wider set is only ever terminated, never
  adopted, so a foreign build cannot be picked up as the live daemon.

## Permission mode switcher

- The mode switcher's digit keys work. Pressing a number selects that mode
  directly, and `esc` closes the switcher. Both were advertised before without
  being implemented, and the digits fell through into the composer.
- The digit handler is live only while the switcher is open, so numbers typed
  into a prompt stay in the prompt.
- The advertised digit range now matches the number of modes actually shown.
  Cycling with `shift+tab` and picking by digit run the same transition, so a
  digit pick cannot skip the auto mode opt-in.

## Readable failures

- A message that fails to send now wraps its error across lines instead of
  truncating to one. The remediation for these failures sits at the end of the
  message, which is exactly what truncation removed.
- On a system where AppArmor restricts the user namespace the sandbox needs,
  the installer says so and prints the profile commands. Previously this
  surfaced only when a first message failed with a sandbox probe error.
- `agenc doctor --apparmor-profile` explains why it cannot generate a profile
  for a source or npm install: the profile grants its exception to one exact
  verified binary path, which only the standalone installer manages.

## Correct login state for configured providers

- The footer no longer claims you are not logged in when your provider comes
  from `config.toml` rather than an environment variable. Provider detection
  read only the environment, so a working session against a configured
  provider was reported as unauthenticated while it streamed normally.

## Upgrading

Standalone installs: `curl -fsSL https://get.agenc.ag/install.sh | sh`

npm installs: `npm install -g @tetsuo-ai/agenc@0.15.0`

No state migration is required. Existing daemon records are read as they are,
and the first run of the new build stops any superseded daemons still serving
your home.
