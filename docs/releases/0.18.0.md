# AgenC 0.18.0

AgenC 0.18.0 adds `/goal`, a session goal that keeps the agent working until
runtime verification and an independent reviewer both agree it is met. It
removes the embedded editor and the terminal workbench, widens the provider
lineup, and makes unattended runs stop for a reason instead of drifting. Long
sessions survive compaction pressure through a degradation ladder rather than
ending the turn, and truncated provider streams are retried instead of being
reported as answers.

This release removes shipped surfaces. Read **Removals and upgrade notes**
before updating.

## Goals

- **`/goal <objective>` keeps a session working toward one stated end.** The
  goal is structured state outside the conversation, so compaction cannot lose
  it, and it is re-stated every round. Each round the runtime runs the
  verification commands itself in the sandbox and treats exit codes as ground
  truth, rather than believing a claim that the tests passed.
- **An independent reviewer decides completion.** A fresh, tool-less context on
  a configurable model reads the objective, the verification results and a
  bounded diff — never the worker's transcript — and returns met, not met,
  impossible or blocked. Malformed output gets one repair turn and then counts
  as not met; it never counts as a pass.
- **Budget exhaustion is not completion.** Round, cost and deadline limits
  settle as `budget_exhausted` with the progress so far and the next step.
  A goal that stops making tool progress settles as `stalled` and hands control
  back. `/goal` also reports `pause`/`resume`, rounds, elapsed time, spend and
  the last verdict.
- **Tamper detection on the verification surface.** The diff since the goal's
  base commit is checked against the verification scripts and test globs, and
  hits are shown in status and handed to the reviewer. A default constraint
  forbids weakening checks to make them pass.
- **Headless.** `agenc -p "/goal …"` runs the same loop without the TUI.
  Clients drive it through the `session.goal` RPC (daemon protocol 1.14):
  `get`, `set`, `clear`, `pause`, `resume`. See
  [reference/goal.md](../reference/goal.md).

## Removals and upgrade notes

- **The terminal workbench is gone.** The sidebar file explorer, the
  Agent/Editor tabs, the embedded Neovim buffer, edit proposals, code
  prediction and the agents rail are removed. The plain fullscreen layout is
  now the only TUI layout.
- **`/vim` composer mode, the vim motion engine and the ctrl+g external editor
  are removed.**
- **Config:** the `[buffer]` section and `tui.vim_mode` are removed. The legacy
  `editorMode` field is dropped by migration with a notice; no action is
  required beyond deleting the keys if you set them.
- **Daemon protocol 1.15 removes the 18 `workspace.editor.*` methods** and the
  status-line `vimMode` presentation field. This is the protocol's first
  non-additive revision. Negotiation compares versions and not method sets, so
  an older client still completes `initialize` and then receives
  `METHOD_NOT_FOUND` for those calls. No published package used them.
- **The `editor_request_failed` stop reason is removed** along with the Editor
  turn it described.
- **The retired `WebFetch` implementation is removed.** `web_fetch` is the
  supported surface.
- Internal-build `USER_TYPE` gates and vendor experiment names are gone from
  the runtime.

## Providers and models

- **New providers:** Ollama Cloud (direct), Cerebras, native Kimi, and
  QwenCloud. Local providers now resolve their real context window instead of
  assuming a default, and local models are admitted with provider-local slugs
  at zero cost.
- **DeepSeek V4.1** is supported on the native and managed routes, including
  image input, tool image relay and automatic tools on the managed route.
- **MiniMax** gains the current model lineup, the M3 thinking switch, split
  reasoning replay and H3 video.
- **Reasoning controls match what each API actually accepts.** GPT-5 gets the
  effort ladder its API accepts and the Fast tier across the family; Anthropic
  gets the thinking control each Claude generation accepts, a clamped manual
  thinking budget and fast mode on the priority tier; Gemini 3.x Flash models
  are registered with their verified thinking levels.
- **OpenRouter supports request-level zero data retention** through
  `[providers.openrouter] zero_data_retention`.
- **A billing refusal is terminal, not a rate limit.** Z.AI plan and quota
  refusals, and xAI spending-limit refusals, are now named as what they are
  instead of being retried as throttling or reported as auth failures.
- Gemini JSON Schema handling uses native schema fields, accepts `anyOf`
  without a parent type, and collapses type arrays on the wire. MCP object
  schemas that omit `type` are accepted.

## Unattended runs and routines

- **Unattended runs get a deadline, a reserve and a graceful stop.** A run that
  reaches its limit stops on purpose, with the remaining budget reserved for a
  clean wind-down instead of being cut mid-effect.
- **An unattended run can do read-only work by itself** and reach the folder,
  the catalog and an end without an approval prompt, while shell reads stay
  confined to the run's own folder.
- **A blocked routine explains itself.** Runs stopped by permissions report the
  rule that stopped them rather than failing silently, and a call that got
  nowhere is not retried forever.
- Routine agents receive the daemon's client environment, and bounded macOS
  diagnostics are admitted while denied outcomes are preserved.

## Context, compaction and long sessions

- **Compaction degrades through a ladder instead of ending the turn.** When a
  summary cannot shrink the context enough, the runtime steps down through
  progressively stronger reductions rather than stopping with `compact_failed`.
- **Compaction transactions have a 900 s wall budget** and name the cause and
  size facts when a durable commit fails, instead of hanging.
- **Accounting matches what is actually sent.** Retained provider reasoning and
  the current phase are charged into compaction pressure, shrink is measured on
  the image-bounded request, and the summarizer's own source is canonicalized
  with its own budget.
- **Images are bounded on the wire** and the image budget is applied after
  fresh attachment assembly, so recent images survive within the request
  budget.
- The fallback token estimate learns its undercount from provider-reported
  usage, and a provider that reports no usable count no longer produces an
  unbounded compaction output.

## Reliability

- **A stream cut before its terminal event is retried, not answered.** A strict
  SSE stream that ends without a terminal signal is treated as a retryable
  truncation, and a stream cut by a transport fault is re-sampled before any
  tool call runs.
- **Empty model responses retry through a backoff ladder** when unattended
  (three attempts), once immediately when attended, and the provider
  continuation is reset on the later attempts.
- **A poisoned completion gate stops the turn as `effect_review_required`**
  instead of livelocking, and a looping failure-cause chain is bounded so it
  cannot hang the turn.
- A file mutation the transaction proved harmless settles as
  `confirmed_no_effect` rather than leaving the session's side-effecting tools
  gated behind `/resolve`. The same applies to browser tools with no
  executable, provider-rejected image requests, and `apply_patch` planning
  refusals.
- `web_fetch` settles its own admission at zero, so a fetch can no longer mark
  the session cost unknown.

## Daemon, protocol and sessions

- **The daemon protocol moves from 1.2 to 1.15.** 1.11 adds
  `session.statusLine.execute`; 1.12 adds the effective permission mode and
  pending tool approvals to run inspection; 1.13 adds
  `session.processes.list` / `session.processes.stop`; 1.14 adds
  `session.goal`; 1.15 removes `workspace.editor.*`.
- **Autostart recovers after a hard-killed daemon.** A stale socket is no
  longer mistaken for a ready one, and the launcher keeps waiting for a spawned
  daemon that is still hydrating.
- **A TUI whose daemon disappeared ends its turn locally** after a 10-second
  silent-daemon probe, instead of appearing busy forever.
- Recovered sessions serve their persisted transcript by session id, the
  transcript snapshot reports the runtime's live turn, and message ids are
  collision-resistant.
- Session control-plane ownership, attachment and shutdown ownership, and
  runtime-generation isolation are enforced, so an old command cannot act on a
  newer session.

## Permissions and sandbox

- **Relative rules are anchored the way targets are resolved**, and a trusted
  project is recognized under every spelling of its path.
- **The original protected roots stay explicit-user-only.** An output-format
  option is no longer read as a disk format.
- The sandbox supports stable workspace prefix aliases, lets media tools
  declare their output directory, lets file tools write the durable memory
  roots under `workspace_write`, and makes MCP stdio work and fail legibly on
  Landlock-fallback hosts.
- `FileRead` and `apply_patch` can reach the owning session's plan file;
  approvals are invalidated across session resets.

## Plugins, skills and MCP

- **Plugin signatures survive publisher key rollover**, remote-source updates
  require signatures, bundled remote-marketplace installs verify them, and
  local plugin sources must be declared explicitly.
- **Plugin bytes are checked out verbatim on Windows** so signatures verify
  there.
- The official marketplace refreshes instead of serving a stale copy forever,
  and credentials are redacted from git marketplace sources, native archive
  fetch errors and plugin update output.
- Skill invocation effects are serialized, skill identities are preserved while
  display labels are exposed, and the context-scaled listing is capped.

## CLI, TUI and onboarding

- **`--bypass-approvals`** skips approvals while keeping the OS sandbox.
- **Headless session continuation:** `-c -p` and `--resume -p` continue an
  existing session in print mode, which now writes each assistant message once
  and sends one-shot text prompts byte for byte.
- **Onboarding picks theme, provider and model access with the arrow keys**,
  and validates local-model setup as you go.
- **`grok-login` uses the device flow over SSH** and lets the URL be copied,
  instead of stranding a remote session on a browser redirect.
- `AskUserQuestion` is hidden in one-shot print mode, where nothing can answer
  it.

## Language servers and memory

- **Language-server diagnostics are folded into edit results**, and servers
  start without explicit configuration.
- **Durable memory works end to end for the coding agent**: the extraction
  cadence persists across a restart, drafts stay on the canonical home, and the
  saved-memory notice is kept out of the conversation.

## Evaluation

- A Harbor adapter and recipe for **Terminal-Bench 2.0**, a three-agent
  benchmark runner, and multi-prompt session tasks that measure the coding loop
  rather than single completions. The full 2026-09-12 run of main on DeepSeek
  V4 Pro scored 61 of 89; the harness review and comparison are in
  [eval/terminal-bench.md](../eval/terminal-bench.md).

## Gateway

- Media quota is reserved before provider calls, pairing state transitions are
  serialized across processes, streaming delivery failures are observed
  immediately, and the installed service home and executable arguments are
  preserved across restarts.
