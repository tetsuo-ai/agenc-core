# AgenC 0.14.1

AgenC 0.14.1 is an emergency patch for every machine that upgraded from 0.13
to 0.14 with existing sessions on disk. If your daemon stopped starting after
the 0.14.0 update, this release fixes it. No data is lost and no manual
cleanup is required.

## Daemon startup

- 0.13 and earlier wrote session journals with rollout schema version 1.
  0.14.0 rejected those journals during admission recovery and treated the
  rejection as fatal, so one legacy session in any project prevented the
  daemon from starting for every project. 0.14.1 reads schema version 1
  journals again, matching the documented compatibility policy: only journals
  newer than the running version are unreadable.
- A project whose recovery genuinely fails (a damaged journal, an unreadable
  database) is now excluded from admission and reported on stderr with its
  project directory, database path, and reason. The daemon keeps starting and
  keeps serving every other project. The excluded project is never served
  partially recovered; its next use re-runs recovery and reports the same
  failure directly to that caller.
- Schema version rejections now name the version found and the supported
  range instead of a bare "not supported by this runtime".

## Visible failures instead of silence

- A prompt that fails to submit no longer looks like the composer ate it.
  The TUI shows a persistent "Message not sent" error with the reason, in
  the workbench footer as well as the classic layout. Previously the error
  flashed for three seconds in an area the workbench frame clips, then the
  prompt text quietly reappeared in the composer.
- Connection errors now explain themselves. When the daemon socket refuses a
  connection, the TUI and headless mode append the tail of the daemon's
  startup log to the error, so "connect ECONNREFUSED" arrives with the actual
  startup failure that caused it.

## Upgrading

Standalone installs: `curl -fsSL https://get.agenc.ag/install.sh | sh`

npm installs: `npm install -g @tetsuo-ai/agenc@0.14.1`

No configuration, session, or state changes are required. Sessions written by
0.13 are read in place and upgraded on their next use, as intended.
