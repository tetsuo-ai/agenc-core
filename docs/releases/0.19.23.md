# AgenC 0.19.23

AgenC 0.19.23 keeps the OpenAI prompt cache when a session loads a tool,
changes its reasoning effort or resumes, and resumed sessions count their full
cost. The daemon answers about a second after it starts, even with hundreds
of saved sessions. The prompt no longer says the network is restricted when
nothing blocks it. On macOS, removing old runtimes no longer waits on an
unrelated drive.

## OpenAI prompt cache

- Loading a deferred tool no longer changes the tool list at the start of the
  request. Responses API models receive the loaded tools as `additional_tools`
  items after the conversation, so the next request reuses the cached prefix.
  Other providers keep their request shape (#3332).
- Changing the reasoning effort during a session keeps the cache on GPT-6
  models: AgenC sends OpenAI's `configuration_update` item instead of a new
  prefix (#3332).
- In a measured Light session that loads two tools and changes the effort
  once, the cost fell by 45% on GPT-6.1 Terra and by 37% on GPT-6 Luna
  (#3332).
- A resumed session (`agenc -c`, `agenc -c -p`) sends the same request prefix
  as before the resume. Attachment state and Responses function call ids are
  kept, and the session context carries today's date (UTC), which changes once
  a day, instead of the current time. The first resumed request reads the
  conversation from the cache instead of writing it again, which made it about
  90% cheaper in the measured sessions (#3333).
- After `agenc -c -p`, `cost-totals.json` adds each resumed turn to the session
  total. Before, it kept only the cost of the last turn (#3333).
- An OpenAI `server_error` that arrives in the stream before any output is
  retried with the same bounded policy as an HTTP 5xx (#3333).

## Daemon start

- The daemon answers status, health and new sessions about a second after it
  starts. It now lists the saved sessions at start and restores each one when
  a request names it. Before, it restored every saved session first, so with
  hundreds of them the TUI looked stuck and `agenc daemon status` could time
  out for about two minutes (#3338).
- Memory at start stays low. In a test home with 230 saved sessions and 5.7 GB
  of state, the daemon used about 220 MB 28 seconds after start instead of
  2.3 GB. Saved sessions still show in the session list and resume as before
  (#3338).

## Network wording in the prompt

- The prompt says the network is restricted only when a sandbox actually
  blocks it, and the model installs missing tools when it is allowed to.
  Before, with the dangerous flag or in bypass mode on a host without a
  sandbox, the prompt said the network was restricted and the model gave up
  on installs (#3340).

## macOS runtime cleanup

- Removing old runtimes after an update no longer runs `lsof`, which could
  hang when an unrelated drive was stuck. A helper that ships with the runtime
  asks each process for its open files and folders and never lists the
  mounted drives. The whole check has a 30 second deadline. When it cannot
  finish, AgenC keeps the old runtime instead of removing it (#3339).

## Upgrade notes

Standalone installations update with `agenc update`; npm installations with
`npm install -g @tetsuo-ai/agenc@0.19.23`; Homebrew installations with
`brew upgrade tetsuo-ai/agenc/agenc`. Then run `agenc daemon restart`.
