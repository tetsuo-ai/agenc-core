# AgenC 0.16.0

AgenC 0.16.0 adds the grok-4.6 model as the new startup default, ships a
first-party security plugin, and settles a class of failure where a workspace
could be left permanently unusable by state a dead process left behind. Most of
it came out of driving a source build as an ordinary user and fixing what got
in the way.

## Models

- **grok-4.6 is catalogued and is the startup default.** xAI shipped it on
  2026-08-12; it carries a 500k context window, text and image input, tools and
  structured output, and reasoning `low`/`medium`/`high`/`xhigh` defaulting to
  `high`. `xhigh` is new to the Grok family and gets its own reasoning tuple, so
  the highest effort tier is actually reachable from the picker rather than
  silently dropped. The default moved in every place it is written — provider
  default, env resolution, shipped config, startup selection, and the heartbeat
  admit fallback — and the model was added to the vision-with-tools set so a
  turn containing an image keeps function calling.
- Below 200k prompt tokens grok-4.6 bills exactly as grok-4.5
  (`$2` in / `$0.50` cached / `$6` out per 1M), so it reuses that cost tier and
  `dollar_cap` enforcement stays correct. Above 200k, xAI doubles the rate and
  the cost table has no prompt-size tier yet, so a very long turn is
  under-counted rather than over-counted — the safe side, since over-counting
  would trip budgets early on every short turn.

## Plugins

- **A plugin that ships inside the runtime package can now be enabled by
  default**, without opening the `plugins.enabled` auto-discovery gate. That
  gate still defaults to false: it governs loading whatever `plugins/`
  directory the repository you happen to open contains, which a third party can
  forge and which may carry hooks that execute commands. A plugin compiled into
  the package we published is not forgeable, so it is registered through the
  built-in registry and enabled by default, while a user can still turn it off
  in `/plugin`.
- **`zeroday-hunter` ships as the first such plugin** — exploit-first source
  auditing that runs a campaign state machine (frame → map → audit → prove →
  falsify → report) with quantitative gates, deterministic PoC verification, and
  hashed evidence. It appears in `/skills` and loads through the `Skill` tool,
  with `/skills` and the tool now reporting the same set so the model never sees
  a name it cannot load.
- Workspace plugin auto-discovery also learned to look under
  `<workspaceRoot>/plugins` and `<gitRoot>/plugins`, to accept a `.git` file as
  well as a directory (git worktrees), and to dedupe a local skill that shadows
  a plugin-registered one.

## Workbench and TUI

- **A dead process can no longer leave a workspace permanently blocked.** Four
  independent faults shared one shape: state written by a process that exited
  without releasing it made a live workspace refuse every message, with an
  opaque error and no recovery short of deleting state by hand. Hydrating a
  persisted admission row for a run id bound to two project databases no longer
  excludes the whole workspace; a `collab_agent_status` carrying the real
  `idle` state is accepted by canonical replay instead of being rejected as
  schema drift; a journal binding that points at another project's rollout is
  dropped rather than aborting recovery; and a leftover `disk_authoritative`
  quarantine entry — which asserts the file on disk is the truth — no longer
  counts as protected Editor authority, so tools are not refused when no editor
  is running.
- **Tool output in the transcript is a receipt, not a document.** A succeeded
  Run/Bash row and any tool without a renderer of its own now show one line with
  a `… +N more` note; failures keep their head-and-tail so the verdict survives;
  and text/code edits keep their compact diff, which is the one tool output
  worth reading inline. A fetched page no longer scrolls the conversation off
  screen.
- **The WORKSPACE panel shows the git branch.** Under the file counts it renders
  the branch, upstream divergence, and uncommitted count, resolved on the tree's
  existing refresh so it costs no extra git process and never shows a stale
  branch. Clicking it opens a read-only detail panel with HEAD, subject, author,
  date, repository root, and the status breakdown.
- **The running-agent row is a dot bar that fills with work** — one dot per tool
  call, grey to bright, wrapping past a full bar — instead of a marker walking
  along a line. It measures work done, not an invented completion percentage.
  The same running star now marks every in-flight label in the transcript: a
  tool call, a permission wait, a classifier check, a wait on other agents.
- The bundled **iot-builder** skill for embedded/IoT development ships in this
  release: measurement-first board identification, per-board and per-toolchain
  references, a failure playbook, and a hardware-inventory convention.

## Runtime and recovery

- **A streaming fallback is no longer re-rolled when the model returns the same
  bytes.** Discarding a partial answer and asking again only helps if the next
  attempt differs, and sampling does not guarantee that: an observed turn
  degenerated into repeating one token until it hit the output cap, and
  consecutive attempts came back byte-for-byte identical. The retry budget
  exists for transient stream drops, so an identical partial now surfaces the
  failure instead of spending the remaining re-entries reproducing it.
- The context window is reserved for provider-native server-tool turns, so a
  turn that hands work to a server tool is not mis-accounted.
- Descriptor directory paths on darwin are pinned by inode identity, and file
  URIs are built and compared as URIs rather than string-interpolated, so a path
  with unusual characters compares correctly.
- The token-accounting fallback counts tokens, not bytes, and a Write guard
  refusal settles as `confirmed_no_effect` instead of an unresolved mutation.

## Tests and CI

- The default suite is gated in CI, and the hosted-platform lanes no longer
  time the runner instead of the editor: a fixed startup bound was turning
  runner variance into red pull requests on healthy changes, so the bound now
  fires as the diagnostic it was meant to be. Several suites were realigned
  with the UI and defaults their own changes shipped, the modified-since-read
  refusal test now actually exercises the guard, and the repo root is resolved
  as a path instead of a percent-encoded URL.

The embedding SDK package stays independent at 0.3.0.
