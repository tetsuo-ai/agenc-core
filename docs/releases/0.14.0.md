# AgenC 0.14.0

AgenC 0.14.0 makes large, long-running agent jobs safer to resume, faster to
navigate, and easier to inspect when something goes wrong.

## Workflows and batch agents

- Version-2 workflows run dependency graphs of up to 1,024 steps. A step can
  start as soon as its own prerequisites finish instead of waiting for
  unrelated work.
- Step and group outputs are committed as bounded, digest-bound handoff
  artifacts before dependent agents receive them. Failures, cancellations,
  unknown outcomes, and blocked dependencies remain explicit.
- CSV agent jobs now survive restarts with bounded scheduling, paginated
  inspection, and operator review for work whose external outcome cannot be
  proven safely.
- Cancelling a large agent tree now uses indexed, set-based database operations
  instead of repeatedly walking the same descendants.

## Recovery and long sessions

- AgenC no longer assumes that a command failed merely because its caller
  timed out. It keeps tracking the physical operation until the durable outcome
  is known, preventing unsafe automatic retries and duplicate side effects.
- Damaged, incomplete, reordered, or unauthenticated session journals are
  quarantined instead of being partially replayed. `agenc state recovery`
  commands support bounded inspection, rescan, retry, and abandonment flows.
- Versioned checkpoints bind every tool result to its exact call, order, body,
  and digest. Changed, truncated, duplicated, or mismatched results cannot
  silently enter a resumed session.
- Conversation compaction is transactional: it commits completely or leaves
  the original history intact. `/compact-rollback` restores retained source
  history, and `/compact-retain` extends the rollback window.

## Search, memory, and editing

- Fuzzy file search now keeps a persistent workspace index, refreshes it after
  filesystem changes, and reports whether results are fresh or degraded instead
  of repeatedly crawling the repository.
- Memory recall searches the full saved-memory corpus rather than only the
  newest entries, so older but relevant project knowledge can return.
- `apply_patch` now uses bounded linear traversal and matching for large
  patches while preserving LF, CRLF, mixed line endings, UTF-8 BOMs, and
  missing final newlines exactly.
- Grep, Glob, and Orient use AgenC's packaged ripgrep through a bounded,
  byte-safe protocol that preserves exact path identity and rejects executable,
  configuration, and output-substitution edge cases.
- The Agent/Editor workspace and Neovim edit window shipped in 0.13.0. This
  release hardens their ordered input delivery, partial UTF-8 handling,
  lifecycle cleanup, and ambiguous-acknowledgement recovery.

## Providers and networking

- Token accounting now covers the complete provider request, including system
  instructions, messages, tools, schemas, media, framing, and reserved output.
  Anthropic, Bedrock, and Gemini use native counting when they can represent the
  complete request; other providers use a conservative bounded fallback.
- Reconnects now use finite full-jitter backoff and strict `Retry-After`
  parsing while preserving the rule that uncertain side effects are never
  retried automatically.
- Homebrew installation now preserves the flattened self-contained AgenC
  runtime correctly.

## Measured improvements

- On the recorded Node 26.5.0 benchmark machine, the synthetic 32,000-hunk
  delete-patch parser case improved from a 355.8 ms median in artifact commit
  `3431a40ea` (source `925f3ec2860abf48e0c6c0830d135da2587a4d69`, JSON
  SHA-256 `8c72fc88fd10dfde2f91bd7cc3ce8028af552781b7b699db9931529cac0abd07`)
  to 11.5 ms in the current artifact (source
  `dc10a164573d5556797f4bd8c913f71774afc923`, JSON SHA-256
  `696b9534fba13177bc135247c7c91c53be4a3e0dfd23001cb3180981c765701b`):
  31.0x for this parser workload. This is not a claim that every edit is 31.0x
  faster.
- In the fixed memory-recall test containing three old relevant memories and
  220 newer distractors, the newest-200 baseline found 0 of 3; the full-corpus
  index returned all 3 as the top result.
- In the deterministic offline compaction test, the production planner plus a
  local extractive test proxy retained 16 of 16 facts while reducing bytes by
  74%, compared with 3 of 16 for a tail-only baseline. This test performs no
  provider calls and does not claim live-provider summary quality or latency.
- Recovery is exercised at one million journal events, cancellation at 100,000
  nodes, workflow scheduling at 1,024 steps, fuzzy search at up to one million
  paths, and compaction at 100,000 history references plus a 64 MiB payload.
  These are bounded scaling gates, not cross-machine speed claims.

## Breaking changes and migration

- State database migrations 17 through 24 run automatically. Legacy records
  remain readable and are preserved or upgraded through the reviewed migration
  paths.
- New effect-evidence and transactional-compaction records require a 0.14
  reader. Once 0.14 opens and migrates an `AGENC_HOME`, 0.13 refuses that state
  database; downgrading that home is unsupported.
- Raw protocol-1.0 clients can still use the earlier
  `session.resolveToolCall` request shape for a legacy in-flight tool call that
  has no durable effect record. Durable effect records require the exact tool
  call, disposition, evidence reference, and evidence digest; a legacy request
  leaves those protected records pending instead of inventing review evidence.
- The obsolete TypeScript `BudgetLedger`, `BudgetEnforcer`, and pricing-adapter
  exports and direct runtime subpaths have been removed. Source integrators
  must use the SQLite-backed execution-admission APIs.
- SDK source includes new typed CSV-job and workflow handoff/result surfaces,
  but `@tetsuo-ai/agenc-sdk` remains independently versioned at 0.3.0 and is
  not published by this launcher/runtime release.

## Upgrading

```sh
agenc update                              # standalone installs
npm install -g @tetsuo-ai/agenc@latest   # npm installs
brew upgrade agenc                       # Homebrew installs
```

Restart an already-running daemon after updating:
`agenc daemon restart`.
