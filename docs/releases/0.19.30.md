# AgenC 0.19.30

AgenC 0.19.30 sends a smaller first tool list in native DeepSeek Light, so every request of a short task carries
fewer tokens, while a long task still keeps its cached prefix. An image that leaves the context to make room is now
marked as already shown, so the model records what it needs instead of reading the image again. A Light request
that asks for helpers now gets them, tool search finds `spawn_agent` for agent queries, the Light instructions name
only the editors the tool policy allows, and `apply_patch` names the hunks that overlap.

## Prompt cache and tokens

- Native DeepSeek Light starts with a compact core tool list. `exec_command`, `write_stdin` and `kill_process` carry
  the fields used to run, poll and stop processes and to ask for approval, and `FileRead` and `system.searchTools`
  use their short forms. The tool schemas in the first request take 4,301 characters instead of 6,568. On a sample
  workspace with DeepSeek Flash the first request costs 2,321 input tokens instead of 2,938 (#3402).
- Starting, polling or stopping a background command leaves the tool list unchanged, so the cached prefix holds.
  The first time the model selects one of these core tools with `system.searchTools`, or a sandbox notice advises
  escalation, the session moves once to the full schemas, the same list as in 0.19.29. A resumed or restarted
  conversation keeps the list it last sent. Fields the compact list leaves out are still accepted (#3402).
- A Light helper agent started by a native DeepSeek session keeps its tool list when its own command yields, so its
  cached prompt holds, and it no longer announces `write_stdin` and `kill_process` as new tools. Its own selection
  of a core tool, or an escalation notice, moves it once to the full schemas without changing its parent (#3398, #3402).
- On native DeepSeek Light, an MCP tool that is listed without tool search (`deferMcpTools = false`, or a policy
  without `system.searchTools`) is announced again when the user names it, with the hint to call it directly, and
  its removal is announced when its server disconnects, as in 0.19.28 (#3398).

## Images

- On providers with prompt caching, native DeepSeek included, an image that leaves the context to make room for
  newer ones now gets a note that it was already shown, and the model is asked to record what it needs from each
  image as it goes. Before, the note invited the model to read the image again, and a task that read every image
  before writing anything could keep re-reading them. An image that no request showed keeps the neutral note (#3397).
- AgenC now remembers every image a request showed since the last compaction. After a model switch, or a request
  that could not carry images, a compaction no longer reports an image as removed before the model could inspect it
  when an earlier request already showed it. Images removed by `/clear` or a manual compaction stop counting as
  shown at the next request (#3397).

## Tools

- When a request in a Light session asks for helpers or sub-agents, the model is now told to load `spawn_agent`
  first, then to spawn the helpers, wait for them and report their results, and to say so when no helper ran.
  Before, it usually did the work itself and could report helper results that no helper produced. Turns that do
  not ask for helpers are unchanged. In the helper scenario of the TUI gate with DeepSeek Flash, 10 of 10 attempts
  spawned both helpers (#3403, #3404).
- `system.searchTools` ranks `spawn_agent` first for agent and sub-agent queries such as "Agent". Before, a search
  for "Agent" returned five other agent tools and left `spawn_agent` out. A search for "read" now ranks `FileRead`
  first, and "ls" ranks `system.listDir` and `Glob` first (#3396).

## Editing

- In Light, the instructions name only the editors the tool policy leaves enabled. With `Write` disabled, native
  DeepSeek Flash is told to use `apply_patch`. With `apply_patch` disabled, it is told to use `Write` for new files
  and full rewrites. With neither, no editing instruction is given (#3401).
- Native DeepSeek Flash describes `Write` with "Use apply_patch for partial changes" only when `apply_patch` is
  available. Otherwise `Write` points to `Edit`, which loads through tool search (#3401).
- When two `apply_patch` hunks change the same lines, the error now names both hunks and the line each one expects,
  and asks to merge them into one hunk. Nothing is written (#3399).

## Approvals, sandbox and remote control

- Approval cards show control characters and escape sequences as visible text, such as `^M` and `^[`, and show
  invisible format characters as `<U+XXXX>` (#3405).
- An approval card shows every line of a shell command, wrapped. A long command ends with a "+N more lines" row, and
  ctrl+w d opens the whole command in a pager. Text that `write_stdin` sends to a running session is shown exactly as
  given (#3405).
- The card's session choice says what approving for the session covers: "any arguments, every <tool> call" for an MCP
  tool, and "all calls", "this action" or "this file" on short cards. When a safety check holds the call, the choice
  reads "this call only, safety check" (#3405).
- `agenc permissions list` and the pending requests that `agenc run` prints show a `permissions [...]` line and a
  `session grant covers ...` line. In JSON, each pending request has a `permissions` list (`tool.use`, plus
  `run_without_sandbox`, `mcp_no_fs_writes` or `single_call` when they apply). Scripts that parse this output may need
  an update (#3405).
- With a whole-tool ask rule, or a PreToolUse hook that answers ask, a call that the tool's own check denies is now
  refused instead of offered on a card. In `dontAsk` mode a hook that answers ask ends as a refusal, while `default`
  and `acceptEdits` still ask. In `auto` mode the safety classifier can refuse a call before a hook's card appears (#3405).
- In the `workspace-write` sandbox, a file write that reaches a protected path through a link or under another name is
  refused and offers to run without the sandbox, like a write that names the protected path. Links to ordinary files
  keep working (#3405).
- Write, Edit, MultiEdit, ImagineEdit and ImagineVideo act only on the file their call was checked against. If that
  file changed in between, they change nothing and ask to run the call again. Image paths with brackets or braces are
  taken literally, and a Write or Edit session grant applies to the exact file name (#3405).
- A nested repository inside the workspace gets the same sandbox protection as the workspace's own `.git`, and
  `git init sub` in the default sandbox now needs the same approval to run outside the sandbox as `git init` at the
  workspace root (#3405).
- In a warm session, a repository you clone or add between two sandboxed commands is no longer treated as one the
  next command created (#3408).
- When a sandboxed command creates a nested repository, its `.git` is now moved aside to
  `.git.agenc-moved-<time>-<id>` instead of being deleted (it is removed only if it cannot be moved), and the
  command's error says where it went (#3408).
- In very large repositories, for example one whose `node_modules` holds thousands of folders, each sandboxed command
  may take a few tens of milliseconds longer (#3405).
- The git status in the footer no longer includes the state of submodules (#3405).
- While remote control is off, the daemon removes a phone pairing left by an older connector, at startup and after
  every reload. If it cannot, for example because the `remote` folder is read-only, the daemon does not start, or
  stops at that reload, and says why. Remove `remote/pair.json` or fix the folder's permissions, then start the daemon
  again (#3405).

## Other fixes

- Three timing-sensitive tests wait on conditions instead of real time (#3400).
