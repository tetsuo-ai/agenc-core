# GPT-6.1 Terra

Verified on 2026-10-28 against OpenAI's [model page](https://developers.openai.com/api/docs/models/gpt-6.1-terra), [GPT-6 migration guide](https://developers.openai.com/api/docs/guides/latest-model), [pricing](https://developers.openai.com/api/docs/pricing), [prompt caching guide](https://developers.openai.com/api/docs/guides/prompt-caching), and authenticated API requests.

The exact model ID is `gpt-6.1-terra`, the only snapshot. It accepts text and images and returns text. It has a 1,050,000-token context window, a 922,000-token input limit and a 128,000-token output limit. The knowledge cutoff is 2026-06-01. Reasoning efforts are none, low, medium (the default), high, xhigh and max. Minimal is unsupported. Sampling temperature is sent only at effort none. OpenAI lists Terra between GPT-6.1 Sol and GPT-6 Luna, so sub-agent routing gives it the balanced prior that GPT-5.6 Terra has.

Standard prices per million tokens are $1 input, $0.05 cached input, $1.25 cache writes and $5 output. Above 272,000 input tokens, the entire request uses $2, $0.10, $2.50 and $7.50 respectively. Fast mode doubles those rates. Batch and Flex are documented at half Standard, but this change adds no Batch/Flex or regional-processing selector. The cache write price is the 30-minute rate. A 12-hour write costs $2.50 ($5 above 272,000 input tokens), but Core never requests 12-hour retention, so that rate is not modeled.

Terra supports Responses, Chat Completions and Batch, not Realtime. Core sends it to Responses unless a session is configured for Chat Completions. The migration guide says Terra's tool calls need Responses. The live API rejected Chat Completions function tools with HTTP 400 when the effort was omitted or set to medium ("use /v1/responses or set reasoning_effort to 'none'"), and returned the tool call at none. A Chat Completions session therefore sends tool turns at any other effort through Responses, as it does for GPT-6 Sol and Luna.

Tiny live checks passed: the model lookup, all six efforts, the medium default when the effort is omitted, streaming, a forced tool call at none and medium, and a Responses tool call and result round trip. `service_tier: "priority"` was served as `fast`. Minimal returned HTTP 400 listing none through max. Temperature was accepted at none and rejected at low on both APIs. Plain Chat Completions answered with and without an effort. Responses usage reports `input_tokens_details.cache_write_tokens`, which Core prices as cache writes. Two end-to-end CLI turns that fixed a bug and ran the script, one at the default effort (medium) and one at none, sent that effort, recorded per-call usage equal to the usage OpenAI reported, and recorded costs equal to these prices.

A second pass on 2026-10-28 checked caching, tools, reasoning and error handling with real CLI sessions (fresh HOME and AGENC_HOME per run, the request body and OpenAI's reported usage captured for every call) and direct API requests.

Caching. Core sends no `prompt_cache_options`, so Terra runs implicit caching with the 30-minute default and Core's per-home `prompt_cache_key`, which OpenAI documents as optional on GPT-5.6 and later and used only for separate cache accounting. Within one session every request repeats the previous one byte for byte and adds to its end: in three-turn sessions each call read the previous call's whole input from the cache except its last 3 tokens, so 89 to 90 percent of all input tokens were cache reads in Light and in standard mode, and the rest were cache writes of new history, which implicit caching writes once at 1.25 times the input price. A new conversation reads the initial developer block (instructions, tools and the first system item) that an earlier one wrote: 1,813 of 1,829 tokens. Changing `reasoning.effort` between two requests of one conversation rewrote the whole prefix (0 cached tokens). A `configuration_update` input item with the new effort kept it (1,809 cached) and the model reasoned at the new effort; Core does not send that item yet. A session resumed with `agenc -c` or `-c -p` rewrites its conversation once on its first request, because the retained auto-mode note, the issued function call item ids and, in standard mode, the session tail's timestamp do not survive the resume; that is tracked separately.

Tools. OpenAI's platform API converts a function tool sent without `strict` into strict mode with every property required, so models fill optional fields they would otherwise leave out (a guessed `timeoutMs: 10000`, a workdir, a 200-line read window). A separate change (#3328) declares `strict: false` on tools with optional fields; on Terra in Light mode it made tasks 4.6 s faster and 10 percent cheaper. Parallel function calls are on and were used in most turns. Replayed function calls carry the item id OpenAI issued. Unlike GPT-6 Luna, Terra decoded at the same speed with the issued id, no id or an invented id (median 82, 88 and 84 visible tokens per second over 8 requests each). With tools at effort none, Chat Completions and Responses answered in the same time (median about 1.3 s each over 6 pairs), so the routing rule above stays.

Reasoning. Terra serves `reasoning.context: "all_turns"` by default, and Core replays the encrypted reasoning of earlier calls by default. With replay on, 16 paired Light runs of 8 tasks took 2.0 s less and 0.6 fewer calls per task than with it off (not significant at this size, 16 of 16 solved either way), so replay stays on. Terra keeps its own reasoning summary default on the platform API, as Luna does: with `summary: "auto"` the first visible output came 0.59 s later (median of 8 paired requests), and 16 paired Light runs finished 2.4 s faster and 6 percent cheaper without it. Medium remains the right default effort: against it, low was 5.7 s faster and 29 percent cheaper per task but skipped a requested test in 1 of 16 runs, and high was 19.4 s slower and 70 percent more expensive with the same 8 of 8 solved.

Errors and limits. With faults injected in front of the live API during `-p` runs, an HTTP 429 with `retry-after: 2`, an HTTP 500, three HTTP 503 in a row and a stream dropped before any output were each retried, and the task finished. An HTTP 400 ended the run at once with OpenAI's message. Every response that reported usage, incomplete ones included, was recorded with exactly that usage and priced at the rates above; when a request may have been billed without reported usage (a 5xx or a dropped stream) the session cost is marked as not fully known. An in-stream `response.failed` with `server_error` before any output ended the run instead of being retried; that is tracked separately. With a user output cap of 400 or 1,200 tokens the needed patch did not fit: the truncated tool calls were not executed, recovery retried four times under the same cap, and the run stopped with a clear message. A command that printed about 15 MB came back to the model as a few hundred tokens, and the model still reported its last line, its stderr line and its exit code. A deferred tool loaded through `system.searchTools` changes the request's tool list, which on OpenAI makes the next request rewrite its whole cached prefix; that is also tracked separately.

OpenAI's [Codex models page](https://learn.chatgpt.com/docs/models) lists `gpt-6.1-terra` for ChatGPT Work and the Codex CLI (0.159.0 or later). This change did not exercise the ChatGPT subscription. Account discovery remains authoritative.

The [OpenRouter live catalog](https://openrouter.ai/api/v1/models) lists `openai/gpt-6.1-terra` (none through max, default medium) and `openai/gpt-6.1-terra-pro` (low through max, default medium). Both have matching limits, image input, tools and OpenAI's per-token prices, including the 272,000-token tier. Both join the bundled catalog at the top, in OpenRouter's order. The `:batch` variants and other catalog changes since 2026-10-21 wait for a full refresh. Their catalog prices remain estimates under the existing routed-price policy; this task made no paid OpenRouter inference calls.

GitHub's [supported models](https://docs.github.com/en/copilot/reference/ai-models/supported-models) list GPT-6.1 Terra as generally available, but the [CLI command reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference) does not list its ID. No Copilot or other unverified provider route is added. An authenticated Copilot list was unavailable.

Context and maximum output limits are documented, not experimentally exhausted. Image input and structured output are documented, not exercised by the tiny live requests. There is no protocol change. Desktop must package a Core revision containing this catalog, pricing and request-routing update; changing Desktop's generated catalog alone is insufficient. Defaults and previous model contracts are unchanged.
