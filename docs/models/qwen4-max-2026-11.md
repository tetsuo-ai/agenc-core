# Qwen4 Max, 2026-11-16

Checked QwenCloud's documentation (`docs.qwencloud.com`, fetched as Markdown with
`curl`) and the live API on 2026-11-16: the Models API on a Token Plan key and a
Pay-As-You-Go key, and a few short chat calls on each. The launch blog renders
only in a browser and was not read; nothing here relies on it.

## Model and access

The [model page](https://docs.qwencloud.com/developer-guides/getting-started/latest-model)
documents one id, `qwen4-max`, with no dated snapshot. It is served on
Pay-As-You-Go (Singapore, Beijing and the Global regions) and on the Token Plan:
the plan's [supported models](https://docs.qwencloud.com/token-plan/personal/token-plan-personal-overview)
list `qwen4-max` beside `qwen4-max-preview`, and the plan's live Models API
returns both. Core registers `qwen4-max` on `qwen` and on `qwen-token-plan`
with one contract and lists it first in both pickers.

`qwen4-max-preview` (alias `qwen4.0-max-preview`) remains a separate Token Plan
model until Alibaba retires it after 2026-11-25. Its entry, limits and effort
values are unchanged: see [Qwen4 Max Preview](./qwen4-max-preview-2026-11.md).
The preview is still refused on `qwen`.

Qwen3.8 Max stays the default model of both providers. Qwen4 Max is new, its
Token Plan Credits rate is not published, and its Light workflow has not been
measured against Qwen3.8 Max.

| Property | Documented contract | Core |
| --- | --- | --- |
| Context | 1,000,000 tokens (input at most 991,808, or 983,616 with thinking) | 1,000,000 |
| Output | `max_completion_tokens` limits thinking and the answer together: 262,144 with thinking, 131,072 without | default and ceiling 262,144 |
| Input | Text, images, video | text and images |

| Structured output | JSON Schema listed; answered correctly live on both routes | off, like every QwenCloud chat model in Core |

## Thinking and effort

The [Chat Completions reference](https://docs.qwencloud.com/api-reference/chat/openai-chat)
and the [thinking guide](https://docs.qwencloud.com/developer-guides/text-generation/thinking)
give `reasoning_effort` the values `low`, `high` and `xhigh`, default `high`.
The API also accepts `minimal` (as `low`), `medium` (as `high`), `max` (as
`xhigh`) and `none` (thinking off). Core offers `none`, `low`, `high` and
`xhigh`, and sends the three compatibility values as their canonical effort.
`thinking_budget` cannot accompany `reasoning_effort`; Core never sends it.

`preserve_thinking` is on by default. Core still sends it and replays earlier
reasoning in the assistant message's `reasoning_content`. A forced tool choice
(`required` or a named tool) is not supported while thinking is on, so Core
sends `enable_thinking: false` without an effort for those requests, as for
other hybrid Qwen models.

Thinking tokens are part of `completion_tokens`
(`completion_tokens_details.reasoning_tokens`) and bill as output.

## Prices and caching

[Pricing](https://docs.qwencloud.com/developer-guides/getting-started/pricing)
lists Singapore rates per million tokens: input $1.5, output $4.5, cache read
$0.075 for both implicit and explicit hits. There are no input-length tiers
and thinking does not change the rate. Core's cost display uses these for
`qwen`. Beijing and Global bill $1.413, $4.24 and $0.071; Core does not model
regional prices.

Implicit caching needs no request field and reports hits in
`prompt_tokens_details.cached_tokens`. The
[explicit cache](https://docs.qwencloud.com/developer-guides/run-and-scale/explicit-cache-qwen4)
(breakpoints, 5m or 1h TTL, writes at $1.875 or $3) is not used by Core.

On the Token Plan the model consumes Credits. No Credits rate for `qwen4-max`
is published, so Core records it as plan usage with no USD amount, like the
plan's other models.

## Endpoints

QwenCloud now documents its own hosts
([regions](https://docs.qwencloud.com/developer-guides/getting-started/regions)):
`https://{region}.maas.qwencloudapi.com/compatible-mode/v1` for Pay-As-You-Go
(`maas.qwencloudapi.com` alone is Singapore) and
`https://token-plan.maas.qwencloudapi.com/compatible-mode/v1` for the Token
Plan. Core keeps its built-in `aliyuncs.com` defaults, which answered the same
on 2026-11-16, and recognizes the new hosts in its check that a key and a base
URL belong to the same billing mode.

## Verification

Offline tests cover the catalog entry and picker order on both routes, limits,
capabilities, each effort value, request bodies with reasoning replay, output
caps, images and tools, the streamed tool-call round trip, the forced tool
choice rule, cost, and the endpoint check.

Live, 2026-11-16, through a build of this change in Light print mode with
default settings, on each route: one turn that ran a shell command through a
tool call and answered from its result, and one turn that read a PNG and named
its colours. All four turns succeeded. Each request carried
`max_completion_tokens: 262144`, `reasoning_effort: "high"` and
`preserve_thinking: true`; the follow-up request replayed the tool call's
reasoning; the image arrived as one `image_url` part and was counted as
`image_tokens`. Implicit cache hits were reported on the second request of a
session. The Pay-As-You-Go cost shown matched the published rates.
